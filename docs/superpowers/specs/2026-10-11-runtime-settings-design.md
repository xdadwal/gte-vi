# Runtime settings

User approved moving report, alert, routing, location, map and refresh settings into admin so operators can tweak them without redeploying. Grid, projection, boundary, graph structure, credentials and infrastructure remain deployment concerns. Anonymous report data changes never add mock-specific UI behavior.

A PostgreSQL singleton contains a revision and typed JSON values. Owner-only writes require CSRF, expected revision and a reason; all operators may read settings. Save/default reset uses the same audited write API. Public GET settings and map snapshots carry the current values; settings outbox events broadcast through existing zone SSE. Backend instances refresh an in-memory settings cache, not a database query per client. Public and admin clients refresh settings on reconnect/polling and apply revisions without reloading the page.

All settings have bounded validation, including alert radius alignment, activation threshold within the rating window, stale timeout above heartbeat/polling and ordered reconnect limits. Values retain existing defaults. Report transactions and saves coordinate through the settings row lock. Shortened expiry caps still-live reports; extended expiry only applies to future submissions. Expired reports are never revived. Aggregation/buffer edits recompute existing zones transactionally and publish updates. Runtime rules use a coherent settings snapshot per operation. Existing routes are marked for recalculation when routing rules change. User radius/sound choices remain personal; radius choices are clamped if the allowed range changes.

Admin uses the existing daylight design, an owner Settings navigation item, grouped numeric fields and color inputs, descriptions/units, a collapsed Advanced section, revision status, save reason, save/discard/default actions and unsaved-change protection. Settings remain accessible directly through /admin, with no public login link.

Validation covers bounds and cross-field errors, auth/CSRF/conflicts/audit, expiry no-resurrection, existing-zone recalculation, cache/SSE/polling propagation, browser configuration and personal preferences. Production capacity is not claimed by these tests.
